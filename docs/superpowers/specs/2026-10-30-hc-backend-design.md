# Optional hc terminal backend

User-approved direction: retain native persistence and add hc as a selectable backend with settings. Default remains webshell; defaultSessionBackend accepts hc. A session never changes backend because defaults change. First release supports installed hc on LightOS targets only, not automatic installation or remote clients/SSH/MicroVM.

Use a standalone target hc executable and its documented JSON-RPC/framed protocol, without embedding herdr-core/Ghostty. Existing agent runtime/version is unchanged. Provider launches hc connect through a non-PTY LightOS exec, as the target login UID/GID, with bounded I/O and controlled environment. Scope core by a stable provider UUID and full selector/login identity. No process-wide environment/cwd changes. Preserve user clones.

hc owns PTYs, screen and scrollback. WebShell owns optional backend tab layout and immutable session mappings, using its existing SQLite-backed optional workspace store. Native target Agent workspaces remain authoritative for native tabs. Tabs can coexist; split inherits its tab backend.

Native id is webshell; new id is hc. Add hc to existing new-tab backend setting and selector, not a persistence boolean. hc missing/incompatible is an explicit error for hc sessions; never spawn native as a fallback. Merely listing targets/backends must not start core or programs. No automatic native-to-hc live migration.

Persist hc lifecycle in a separate SQLite journal keyed by session UUID, with fixed selector/login identity; generic workspace/session snapshots cannot overwrite it. Persist a session creation intent before terminal.run, with deterministic name <=32 chars and provider/session labels. Reconnect performs list/get/attach only. If creation result is unknown, reconcile by exact labels/name including finished terminals; never blindly retry run. Remember the concrete terminal address once observed. Refresh snapshots after every reconnect; hc sequence is scoped to a core process, not a durable replay cursor.

Attach uses hello generation 1 plus framed/attach/status features and a method allowlist (including terminal.read for finished-screen recovery), 9-byte LE frames, maximum 16MiB payload. Dedicated frame reader survives select cancellation. Bound pending queues and writes; DATA credit is granted only after bounded delivery, control traffic remains possible. First paint replaces the browser terminal; no duplicate native history recording or probe/status inference on repaint. hc is the terminal reply authority. Status events are replacement tables mapped to app-owned records. Browser disconnection detaches only, never terminal.kill. Explicit pane/tab close ends only the associated hc terminal; a failed kill must not remove local state or claim success. No server.stop/restart/update exposure.

The default backend setting applies to new sessions only; native remains the default. hcHistoryLines defaults to 1000, is bounded to 0–10000, and applies at the next attach. hc reconnect must preserve terminal identity/PID; unknown backend restoration must fail closed rather than reinterpret as native. Native history files remain intact. hc keep/recovery is not equivalent to rerunning a command: real exits remain final.

Validation: failing-then-passing frame/JSON-RPC, intent/reconcile, close failure, detach, native/hc settings and URL/replay tests; full Rust/Node suites, strict Clippy/rustfmt/docs and frontend build. Real hc isolated-session smoke when tooling permits; never use real user sessions. Release only after all applicable gates pass, publish private tag artifact then explicitly trigger public publish-neko.yml and inspect actual store outcomes.
