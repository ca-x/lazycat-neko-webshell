# Remoted 实施与验收计划

需求源：同日设计稿，含用户后续确认的内置“远程控制”分类、默认关闭总开关、两端手填 Relay 后配对、两种延迟、普通终端/Herdr/文件首版和未来桌面扩展。独立设计审核：已处理 B1—B7 并获准分阶段实现；真实实现与发布仍需独立审核和验收。

1. 完成独立设计审核并处理阻塞项，固定协议、授权及 Android 平台适配合同。
2. 建立共享 Rust 协议 crate：严格输入/长度验证、地址规范化、设备码、成熟 Noise 握手封装、只读方法集合、资源绑定、数据块/游标/取消/错误和延迟过期状态；先验证真实两端互通及拒绝路径。
3. 实现 CF Worker + Durable Object，真实本地 Worker WS 测试，配置及可复现部署说明。中转不承载应用权限，不实现任意HTTP代理。
4. 实现应用级后端 remoted：默认关闭、持久化设备与资源绑定、管理API、连接监督、批准/拒绝、权限降级/撤销串行化，复用现有目标授权。三类数据适配器分模块，不扩大 main.ts，不改变 agent 生命周期。
5. 新增独立 settings/remoted 前端目录，现有设置仅编排；明确状态/延迟、逐步显示配对及设备管理；light/dark/小屏/键盘验证。
6. 建立独立原生客户端：先设计标准/tokens/controls，NSH 真实 API，Android app-owned 扫码和 Keystore 适配（框架本体不修改），再实现两端连接/配对/会话/Herdr/文件页及协议和UI测试。
7. 真实端到端验证：跨 Relay 认证、三类业务、并发/流控、只读、撤销、断线恢复、主题与 Android 安装及平台能力；未有设备的验证必须明确说明，不冒充通过。
8. 代码及安全/UI复审，完整仓库检查与客户端构建，更新用户文档与版本；小橘 tag 构建→公开仓库发布，原生客户端以独立组件发布；核对 Release 附件、版本、SHA256、商店提交结果，保存发布记忆。

发布前任何核心数据面/权限/扫码/构建阻碍都要如实保留，不能发布仅有设置入口的版本并宣称功能完成。
